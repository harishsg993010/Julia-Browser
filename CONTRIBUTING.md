# Contributing

Thanks for helping with Julia Browser. Bug reports, site compatibility reports and pull requests are welcome.

## Reporting a site problem

Include:

- the URL and the command you ran (`julia-browser browse <url>` or the agent commands)
- what you expected and what you got (Markdown output, screenshot, error)
- a log with `JB_TRACE_JS=1`

If the page renders differently in Chrome, compare against headless Chrome:
`chrome --headless=new --dump-dom <url>`.

## Building

```bash
make build-dev      # debug build with --features screenshot,images
make build          # release build (LTO, several minutes)
```

Always build with `--features screenshot,images`. Without them, layout, images and screenshots are
missing, and many tests behave differently.

## Where things live

| Path | Contents |
| --- | --- |
| `src/` | The engine: HTTP, parsing, rendering, SDKs, CLI, CDP server, sessions, vault |
| `src/js/` | SpiderMonkey runtime and host operations (`runtime.rs`, `host.rs`, `mod.rs`) |
| `src/js/env/*.js` | The browser environment (DOM and Web APIs), loaded in file-name order |
| `src/layout/` | blitz-dom layout, visual order, character-cell view, screenshots |
| `src/bin/wpt.rs` | Web Platform Tests runner |
| `vendor/` | Layout crates with local fixes (`[patch.crates-io]` in `Cargo.toml`) |
| `python/` | PyO3 bindings and the Python package |
| `web-agent/` | General web agent on top of the Python package |
| `benchmarks/` | Agent and research benchmark harness |
| `scripts/` | Real-site checks, WPT helpers, code generators, wheel builds |
| `tests/` | Layout fixtures and golden-file tests |

## Changing the JavaScript environment

- New env code uses `globalThis` and `__jb.currentDocument`, never bare `window` or `document`.
  Worker realms have neither.
- Private fields on DOM objects use the `_jb` prefix. Libraries define their own `_name` fields.
- After adding top-level classes or functions, regenerate the exports with
  `py scripts/gen-exports.py`.
- `67_editing.js` is generated by `py scripts/gen-editing.py`, and `96_idl_data.js` by
  `node scripts/gen-idl.js`. Do not edit those two files by hand.
- Check the syntax before building, which takes a second:
  `node -e "new Function(require('fs').readFileSync(process.argv[1],'utf8'))" src/js/env/<file>.js`

## Testing a change

1. `make test` for the Rust tests.
2. `make interact-check` for real-site interaction scenarios.
3. For DOM or Web API changes, run the affected WPT suites before and after, and compare them:
   `py scripts/wpt-diff.py OLD.json NEW.json`. Also run the regression sample:
   `make wpt SUITE=html/semantics/scripting-1,html/webappapis,html/dom/elements,dom/events`.

## Pull requests

- Keep each change focused, and say how you tested it.
- Match the surrounding code: naming, comment density, idioms.
