# Guide for coding agents

Julia Browser is a headless browser for AI agents, written in Rust. Pages run in SpiderMonkey
(`mozjs`) against a DOM written in JavaScript (`src/js/env/*.js`). Layout uses blitz-dom (Stylo +
Taffy + Parley). See [CONTRIBUTING.md](CONTRIBUTING.md) for where things live.

## Build

- Always build with `--features screenshot,images`:
  - `cargo build --features screenshot,images` (debug)
  - `cargo build --release --features screenshot,images --bin wpt --bin julia-browser` (release: LTO, 6–10 min)
- A plain build has no layout, images or screenshots. It silently changes page behavior: image
  sizes are 0, scrolling does nothing, and layout queries fall back to zero-size boxes.
- A release build blocks other cargo commands. Do not edit sources while it compiles.
- Stylo's build script runs `python --version`. On Windows the Microsoft Store `python` alias hangs,
  so put a real Python first on `PATH`. Run repo scripts with `py`.
- A running agent session locks `target/debug/julia-browser.exe`. Run `julia-browser close --all`
  before building.
- Copy each measured build to a numbered name (`target/jb-devN.exe`, `target/wpt-devN.exe`).
  Overwriting an exe that a background run uses kills that run.

## Editing

- For multi-line edits, use an editor tool or a small Python patch script that asserts the old
  text occurs exactly once. Shell heredocs mangle backslash escapes (`\n`, `\t`, regexes) in this
  repo's JS and Rust.
- Files may use CRLF line endings. Keep each file's existing ending.
- Env JavaScript:
  - Use `globalThis` and `__jb.currentDocument`, not bare `window` or `document`. Worker realms have neither.
  - Private fields use the `_jb` prefix.
  - Run `py scripts/gen-exports.py` after adding top-level classes.
  - Never hand-edit `67_editing.js` (generated by `scripts/gen-editing.py`) or `96_idl_data.js` (generated by `scripts/gen-idl.js`).
- Syntax-check an env file in a second before building:
  `node -e "new Function(require('fs').readFileSync(process.argv[1],'utf8'))" src/js/env/<file>.js`.
  A broken env shows only as "Failed to initialise JavaScript environment" on every page.

## Test

- `cargo test --features screenshot,images` for the Rust tests.
- `sh scripts/interact-check.sh <exe>` for real-site interaction scenarios (`ONLY=<regex>` runs a subset).
- WPT: `target/wpt-devN.exe run --root ../wpt --wptserve --filter <suite> --jobs 6 --timeout 20 --out target/wpt-<suite>-N.json > target/spot/<suite>-N.log 2>&1`.
  - Single files: `sh scripts/wpt-one.sh <exe> <path>`.
  - Compare runs: `py scripts/wpt-diff.py OLD NEW`.
  - Heavy suites (css interpolation, big dom/ranges files) need `--jobs 3 --timeout 40` and a quiet
    machine. Under load they time out and look like regressions; rerun those files alone before
    concluding anything.
- Write runner and session output to files, not pipes. A session daemon inherits the pipe and
  `| head` hangs.
- Start long runs (benchmarks, WPT) detached, for example with PowerShell `Start-Process`. Background
  shells die after about 2 hours.

## Debugging

- `JB_TRACE_JS=1` logs scripts, fetches, layouts, slow tasks and budget stops. `JB_PROFILE=1` adds a
  sampling profiler.
- `py scripts/env-line.py <N>` maps `browser_env.js:N` to its env file.
- To tell a site bug from ours, compare with headless Chrome (`--headless=new --dump-dom`).
- Pages behind CAPTCHAs or bot challenges are rendered as served. Do not add code that tries to get
  past them.

## Evals

The harness is in `benchmarks/` (see its README) and the general agent in `web-agent/`. Both use
`claude-haiku-5-5` by default. Keep the model a CLI flag.
